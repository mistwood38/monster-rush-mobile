# 怪潮突围：性能与操作体验优化

继续在 `codex/horde-combat-rework` 开发；对比基线为 `9524454`。没有修改 main、合并或正式发布。

## 实际改动

- 六种普通/精英敌人新增远景关节模型，减少远处无法辨认的牙齿、手指等细节，保留头身、步态和类型标识。高、中、低档分别在约23、17、12米处切换，1.5米迟滞防抖；Boss始终保留完整模型。全部敌人的AI、碰撞、HP与突破惩罚保持运行。
- 怪潮改用漫反射卡通光照，远处动画采样按30/20/12Hz质量档更新。敌人仍按类型批绘；几何分级最多增加6次绘制，不能只用调用数判断性能。
- 主角和当前战甲共享原骨骼的淡青色遮挡提示，只在近身敌人可能遮住角色时启用，实际深度测试决定显示哪些像素；无遮挡时关闭，战甲解除时随本体淡出。
- 数字门保留从进入到通过角色的领取窗口，允许晚一步侧移。一次只领取一扇，完全经过后不能补领。修复招募门忽略职业字段的问题。
- 普通远程敌人错开发射，至少约0.35秒分隔前摇，预警0.7秒；同时普通敌弹预算随阶段从5升至12，Boss期间4。达到预算的敌人等待再攻，不删除已发子弹。Boss独立技能、近战与突破伤害保留。
- 正式队员、宠物、战甲、词条与存档核心配置未调整；更新PWA缓存与自包含审查包。

## 证据与限制

安卓真机、温升和触控延迟未验证，不能将云端SwiftShader结果当作手机FPS。程序模型和动作仍需要专业美术细修；本次是针对已知问题的优化，不是发行质量验收。

## 功能与生存验证

- `npm test`：36项逻辑/FSM/空间网格检查、45项真实浏览器检查、战甲倒地专项通过；两种竖屏尺寸、触控、五武器、四宠物、三战甲、二十词条、191文件子目录离线缓存均覆盖。300秒逻辑长跑峰值296怪；该长跑提供补给/恢复HP，只证明功能与预算稳定，不当作自然生存。
- `npm run test:optimization`：八项新增回归通过，包括迟到领取/过期拒领、职业招募、320怪切换画质保留UID和HP、远程错峰、主角和战甲遮挡提示。
- 自包含HTML为8,876,469字节、153内嵌素材；独立战斗、音频、词条图标以及HTTP零额外资源请求通过。安卓本地HTML打开未测试。
- 重新运行21组×3种子，共63局正常HP模拟；使用原控制器，未恢复HP。每个自然策略合并三流派共9局，完整结果不删失败局：

|自然拾取策略|优化前平均生存秒|本轮平均生存秒|本轮到达观察末尾|
|---|---:|---:|---:|
|站桩（关闭拾取）|50.2|50.8|0/9|
|慢反应扫线|122.5|135.7|0/9|
|中等避险|128.6|137.1|0/9|
|快速避险|112.0|96.6|0/9|

慢反应与中等策略平均有所改善，快速避险策略反而变短，不能声称所有玩家都更容易生存，也不能宣布长线平衡合格。控制器会为避险错过补给，其名称不等于人类水平。共享随机数会受战斗路径变化影响，三种子小样本没有统计显著性结论。观察上限约299.8秒（词条选择占用迭代），完整实际秒数保留。满阶提供组另列，不当作自然成长成绩。

## 隔离渲染对照（最终LOD复用修复版）

同一云端Chromium/SwiftShader，393×873，4队员、160弹丸、64请求火花，冻结AI与时间；每组预热5帧，再采样30个rAF间隔。相同档位锁定，先旧版再新版，运行时没有其他浏览器测试。`before`是9524454，`after`是本轮最终代码。每组活怪数量逐项断言，几何LOD不会减少活怪。

|版本|活怪|画质档|三角形/帧|绘制调用|平均帧时ms|P95 ms|JS堆MiB|
|---|---:|---:|---:|---:|---:|---:|---:|
|before|240|0|161172|46|355.0|383.3|27.8|
|before|320|2|193344|46|282.8|550.0|33.3|
|after|240|0|128980|52|317.8|349.9|29.5|
|after|320|2|120240|52|205.0|300.0|21.6|

320怪低档的三角形减少约37.8%，平均帧时间减少约27.5%。额外远景批次使绘制调用从46增至52，几何缓存由30份增至36份；JS堆随GC时点波动，两个快照不能证明峰值降低。这是用少量额外批次换取更少的几何和光照计算。高档与低档都保留实测P95，不只展示平均值。

此处是静态渲染压力测试，不包括实时AI/碰撞，也不是手机帧率。单次30帧观测会有调度噪声，不能推断所有设备提升比例；软件GPU帧时仍远高于16.7ms，**没有证明达到安卓60FPS**。还需安卓实际GPU、连续怪潮、触控、温升与电耗测试。

[最终原始性能数据](data/performance.json)。[修复LOD复用前的首次测量](data/performance-before-pool-fix.json)也保留，避免隐去试验波动；其中`count`指弹丸数，敌人数应读取`horde.alive`，最终脚本用`requestedEnemies`明确区分。
